# c1 — no universal draft: the lever landscape is deployment-keyed

Contribution 1 of 4. This document wraps the claim's design, its
evaluation protocol, and the obtained data. Values live in
`paper/data/c1_*.json`; figures are produced by
`paper/visualization/fig_c1_*.py` (unified style, single column 1.5:1,
multi column 3:1) into `paper/figures/`.

## design

**Claim.** There is no single best draft-construction lever for
training-free self-speculative decoding. The winner changes along five
deployment axes — architecture, scale, kernel realization,
regime (batch x context x content), and hardware — and choosing wrong
is not a marginal loss: measured wrong-lever costs run 30-60%.

**Falsifiable form.** If one lever config (family, depth K, window,
kernel) were within a few percent of optimal across the measured grid,
C1 would be false and the paper's selector (C2/C3) would be
unnecessary. The naive-strawman is excluded by construction: every
comparison arm is tuned per its own best cell before winners are
compared.

**Why it matters.** Self-spec methods are published as fixed recipes
(KnapSpec: layer sets; EfficientRollout: full-context W4 drafting;
LayerSkip/SWIFT: skip sets). C1 says all of these are points in one
lever space whose optimum moves with deployment — which converts
"which method is best?" into "how do you find the optimum per
deployment?" (C2) and "how do you act on it at runtime?" (C3).

## evaluation

- **e2e protocol**: full serving driver (vLLM LLM API), wall-clock
  including prefill, 8-iteration runs, same-GPU AR anchors; harness
  decode-cell measurements where noted. Speedups are vs each system's
  own AR baseline.
- **beta protocol**: acceptance factor per lever measured at 1152
  paired positions, 16k context, per model column (phase 86).
- **regime suite** (phase 88): 9 canonical regimes on real prior-work
  datasets (GSM8K+AIME, MT-Bench, HumanEval, CNN/DM, NQ-open+ctx,
  WMT14, MATH@T=1.0), serving wall.
- **hardware axis** (phases 75/91): the reference system
  (EfficientRollout) reproduced faithfully on our stack/H100 and
  decomposed against its published A100 numbers; controls isolate the
  draft-context term from emulation tax.
- Provenance discipline: every number is a committed phase artifact;
  refuted pre-registrations are retained (T11).

### headline values

- **Regime axis**: 9/9 regimes beat AR at 8B, but only with K2-K6 —
  the naive K4 grid loses two of them (summarization 0.84x, RL rollout
  0.83x; shallow-K converts both: 1.08x, 1.05x). 32B winners split 5-2
  across kernels plus two skip-composition cells and one honest OFF.
- **Architecture axis**: dense 1.91x (quant+window), MoE 1.15x
  (window-only; the dense chain that wins on dense scores 0.63x),
  MLA: every self-spec lever loses (0.56x at accept 5.9 — acceptance
  is not the binding term; the cost model is).
- **Scale axis**: layer-skip composition stacks at 32B (+3-6%, triple
  composition 1.57x vs KnapSpec's published 1.43x) and is priced out
  at 8B. Skip tolerance rises with scale at every budget (T4).
- **Kernel axis**: the SAME W4A8 checkpoint at identical beta spans
  1.60x (Cutlass) to 2.19x (Humming) at one cell; kernel winners split
  5-2 across the 32B suite.
- **Hardware axis**: the reference system's lever earns 1.24x on A100
  (published) and 0.76-0.86x on H100 (same-stack, measured); their own
  SS B.2 lever ranking inverts across the compute:bandwidth ridge
  (~156 vs ~295). PRE-REGISTERED: our map compiled on A100 should
  select their lever at rollout shapes (blocked on access).


## the grid (phase 93 — the full method x dataset x batch x arch result)

The systematic version of this claim: **FIVE architectures** x four
lever classes (quant ladder incl. activation-quant + 8-bit, window
range {128/512/2048/8192}, search-derived skip sets, kvq — all
ISOLATED single levers; compositions are C2) x 9 real datasets x swept
batch, uncapped generation (clip-audited), every arm on its probed
best kernel. Two layers: Stage A compiled decode cells
(`data/c1_grid_winners_<arch>.json`) and Stage B e2e serving on real
datasets (`data/c1_grid_stageb_<arch>.json`, figures
`c1_stageb_map_<arch>`).

**Stage-B real-data result — five distinct policy surfaces:**

| arch | spec beats AR | winning configs | surface character |
|---|---|---|---|
| dense Qwen3-8B | 32/33 | 5 (Hum-W4A8 K2/K4, win128/512/2048) | rich split; quant↔window crossover along batch AND ctx |
| Llama-3.1-8B | 24/33 | 5 (W4A16 K2/K4, W8-INT8, win512/2048) | dense-like rich surface — C1 generalizes off Qwen |
| Qwen3-32B | 25/33 | 3 e2e (W4-GPTQ K4/K6, skip-K4) + Humming-W4A8 from Stage A | quant-dominant; window/skip at scale |
| MoE Qwen3-30B-A3B | 8/33 | 3 (W4A16 K2/K3, win8192-K3) | OFF-dominant; quant wins concentrate at b32-64 short-output |
| MLA V2-Lite | 11/33 | 1 (W8-chan K2) | OFF-dominant, batch-keyed; T=1.0 sampling kills spec |

No configuration wins across any single architecture's surface, and no
architecture shares another's winner profile — the claim, systematically.

Cross-layer finding (feeds C2): the Stage-A synthetic cells
UNDER-predict MLA/MoE high-batch wins — MoE: predicted 0 vs 8 on real
data; MLA: predicted 4 vs 11 (the pre-repair map predicted only 1, so
part of the MLA gap WAS the cache-collision corruption, and the 4
repaired Stage-A wins are exactly high-batch cells, agreeing with
Stage B's batch-keyed surface) — packed-C4 cells differ from real
prompt-length distributions; selection must be confirmed on
deployment-shaped data.

Realization / integrity ledger (all disclosed): windows on the
FULLCG-scratchpad-minus-wholechain stack (the wholechain single-launch
capture has a localized racy IMA — a throughput optimization, deferred;
fast-gather retained); 32B quant e2e routed to Machete because the
Humming kernel wedges at TP2 odd width (K4/K6 = width 5/7, lazy-cubin
livelock — a KERNEL bug, not a lever/inherent limit; Humming's faster
number stands from Stage A); V2-Lite (base) loops at T=0 on 8/9
datasets so MLA runs at ceiling 2048. A torch-compile CACHE-KEY
COLLISION (SpeculativeConfig.compute_hash omitted the draft config;
fixed in `aaad1c14e`) corrupted several quant arms across campaigns;
all implicated arms are re-measured post-fix (`cells_93v2_*`,
`paper/data/c1_corruption_ledger.md`): dense and MoE winner maps
unchanged, MLA Stage A gains 4 w4a16 cells, llama Stage B moves
23->24/33 — and the one physical-sanity-gate SUSPECT cell (S 6.6,
previously excluded as AR-corrupted) re-measures to a real 1.24x win.
A full-log collision screen of the llama campaign (51 draft boots)
confirms only W4A16<->W8INT8 ever shared a cache directory; fp8dyn,
window, skip and kvq arms are clean. Full gates + ledger:
research/93_c1_grid/README.md.

### status / gaps

- Hardware axis is measured on H100 only; the A100 column is the one
  outstanding measurement (procurement pending).
- 32B R8 spec arms blocked by the Humming odd-verify-width bug
  (upstream report owed); 8B evidence predicts a win there.
- +39.1% fleet value is a labeled prediction from measured cells
  (T11 #7), not an executed fleet run.
- Content-draw caveat (found and closed in phase 94): a b1 cell is
  measured from ONE document, and narrow-window acceptance is
  content-sensitive (across-content CV: win128 12.4%, win512 8.6%, vs
  1.3% for win8192 and 0.3-5.7% for every quant/skip/kv arm). Four
  cells were exposed -- win128 and win512 at b1/c8000 on both arches
  -- and their single draw sat 10-18% below the 3-draw mean. All four
  are re-measured on 3 draws; see `paper/c2.md` "the b1/8k anomaly,
  RESOLVED" and `paper/data/c2_b1_8k_anomaly.json`. Every other cell
  is unaffected: b8/b32 average 8-16 documents, and content-
  insensitive arms do not need the extra draws.
